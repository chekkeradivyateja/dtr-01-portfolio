01 · Description

About

Hi, I’m Divya Teja — a design verification engineer at Maven Silicon in Bengaluru.

My day job is building UVM environments and formal proofs for AMBA-based IP — APB-SPI, APB-UART 16550, AHB-to-APB bridges — and chasing coverage until it closes. On the APB-SPI controller, formal verification in JasperGold surfaced five RTL bugs through vacuous proofs and unreachable covers: corner cases that simulation alone can’t prove.

I came to verification by way of an ECE degree in Guntur, a co-authored journal paper comparing 32-bit complex floating-point multiplier architectures, and a cybersecurity internship at TCS spent parsing logs for the one line that mattered. That habit stuck.

Outside work I build the tools I wished I had. VereChek turns RTL into a compiling UVM testbench and a design-specific verification plan. DV Verification Hub is a free reference for engineers learning the same stack. Money Machine researches, builds and lists digital products on its own, every 30 minutes. The through-line is the same everywhere: find the detail that’s quietly wrong, and fix the cause, not the symptom.

The problem

Every verification project opens with hours of UVM scaffolding — interfaces, agents, sequencers, scoreboards, coverage stubs — before the first real testcase. AI can draft it, but AI-written SystemVerilog that doesn’t compile is worse than none. And shipping an AI tool to machines you don’t control usually means shipping your API key with it.

What it does

Point it at Verilog or SystemVerilog and it generates a UVM or plain-SV testbench, a design-specific verification plan (scenarios, covergroups, SVA assertions), ASCII and HTML architecture diagrams, and a log watcher that turns VCS, Questa and Xcelium failures into file-and-line fix guidance. Local generation works fully offline; AI features are opt-in.

Design decisions

  1. AI output has to earn its way into a file. Rejection-only validators check every AI-proposed assertion, testcase and covergroup — SVA structure, unterminated strings, identifiers outside the interface’s scope, hallucinated transaction fields — and fall back to a safe default rather than embed broken code.

  2. Verified by compiling, not eyeballing. Every design in a 16-design corpus is generated and compiled through a real SystemVerilog frontend (pyslang) against Accellera UVM-1.2, for both UVM and plain-SV output. The first pass found 18 real compile and functional bugs; the corpus now guards against every one.

  3. A log watcher that actually tails. Rewrote watch-log from re-parsing the whole file on every poll — with a fresh AI call per issue, per poll — to byte-offset tailing with rotation detection, tail -f semantics and one AI call per issue, ever. An equivalence checker against the old parser caught two bugs before release.

  4. One-line install, scoped to one client. curl -sSL "…/install.sh?key=…" | bash is gated on the caller’s own license instead of a shared secret: a leaked link exposes one client, and it’s revocable.

  5. Runs on old machines too. Built in a manylinux_2_28 container after a real GLIBC failure on an older client box. It bundles its own CA certificates so HTTPS works wherever it lands, and dead code paths are excluded to roughly halve the binary.

Proof: an AXI4-Lite-to-APB4 bridge

A genuinely complex test design: a five-channel AXI4-Lite slave driving an APB4 master through an FSM, with write/read arbitration and PSLVERR-to-BRESP/RRESP mapping. VereChek parsed all 26 ports, 9 parameters and 5 FSM states, generated a register model, a virtual sequencer and three correctly differentiated agents, and both output flavours compiled clean. With AI on, the plan flagged a write-priority read-starvation risk and a missing-timeout deadlock risk — both planted in the RTL on purpose.

03 · Errata

Bugs I’ve closed

Datasheets publish their errata. These are mine: real bugs in my own tools, what caused them, and how I closed them.

ERR-01 · VereChek · AI engine → CLI

Closed

An error message from the wrong call

Symptom
A real AI failure reached the user as AI: ERROR – None, or as an unrelated error left over from an earlier call.
Root cause
Four wrappers returned a bare None on failure, discarding the real reason (token cut-off, invalid JSON). Callers fell back to a module-level error string that cache hits never reset. And a failure result was a truthy dict, so if not result waved it through as success.
Fix
One error-resolution path for every AI wrapper, explicit failure markers instead of truthiness, the stale error cleared on success, and failures never cached, so a transient 429 or 502 can actually be retried.

Found by an end-to-end run against a real AXI4-Lite-to-APB4 bridge with a live license key.

ERR-02 · VereChek relay · Licensing

Closed

Out of AI quota meant out of the product

Symptom
A client who had used the month’s AI quota couldn’t reinstall or download the tool, so they lost fully local features that never call the AI.
Root cause
Download authorization reused the AI-proxy check, which includes the usage limit. It conflated who you are with how much AI you’ve used.
Fix
A separate identity-only check (active and not expired) gates install and download; the quota gates AI calls alone. Revoked or expired keys stay blocked everywhere. I fixed the architecture, not the limit.

Found by using the product myself: the build’s own embedded key was over its monthly limit.

ERR-03 · VereChek relay · Free-tier hosting

Closed

The 70 MB download that just stopped

Symptom
Intermittent install failures: 502s on cold start, error bodies arriving instead of a binary, and transfers that stalled forever with no error at all.
Root cause
The cold-start wake-up call hit the download endpoint itself, moving the whole binary twice and doubling exposure to the host proxy’s flaky handling of large responses.
Fix
Wake with the cheap /health endpoint. Bound every transfer with --max-time and one retry. Reject any “binary” under 1 MB and print it as the error it is. AI calls retry 429s on Retry-After inside a budget that stays under the client’s own timeout.

Found by chasing intermittent install failures to the one request that made them likely.

ERR-04 · VereChek · RTL parser

Closed

Three ports that vanished without a warning

Symptom
A client’s APB-bridge RTL failed a VCS compile with “too few instance port connections”: PADDR, PWDATA and PRDATA were missing from every generated file.
Root cause
The port-width pattern didn’t allow a backtick, so any port whose width used a `define macro failed to match and was silently dropped.
Fix
Accept macro widths, resolve `define values to literals so generated code never depends on compile order, and keep the design as a permanent regression case.

Found by a real client compile, which is exactly why the regression corpus exists.

ERR-05 · Money Machine · Gumroad API

Closed

Uploads over 100 MB were silently truncated

Symptom
None visible. Uploads reported success; anything past about 100 MB simply wasn’t there.
Root cause
The uploader sent the entire file to the first presigned part URL. Gumroad splits uploads into parts of about 100 MB, so everything after part one was lost.
Fix
Chunk the file across every presigned part and report each part’s ETag on completion. Verified with a real 130 MB two-part upload whose registered size matched the source exactly.

Found by probing how the API splits parts (50 MB → one part, 200 MB → two) instead of trusting a success response.
